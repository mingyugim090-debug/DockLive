# COPY_GUIDE — UX 카피 규칙

1. **사용자의 언어로, 시스템의 언어 금지.** "fixture", "HWPX pipeline", "슬롯 매핑" 같은
   내부 용어는 UI에 노출하지 않는다. 슬롯 → "작성할 칸", 파싱 → "공고 읽는 중".
   (예외: 개발자 문서와 이 하네스 내부에서는 정확한 내부 용어 사용)
2. **버튼은 결과를 말한다.** "제출" 금지 → "분석 시작", "초안 받기", "HWPX 다운로드".
   같은 동작은 플로우 끝까지 같은 이름 (버튼 "내보내기" → 토스트 "내보냈습니다").
3. **에러는 원인+다음 행동.** 사과·모호함 금지.
   나쁨: "업로드에 실패했습니다." / 좋음: "스캔 이미지 PDF는 읽을 수 없어요.
   공고 텍스트를 붙여넣으면 이어서 분석합니다."
4. **빈 화면은 행동 초대장.** 설명문 대신 첫 행동을 바로 놓는다.
5. **문장형·존댓말·간결.** 마침표까지 한 호흡. 느낌표 남용 금지. 이모지 금지.
6. **근거를 약속하는 브랜드 보이스 유지**: "공고가 근거, 평가기준이 기준" 톤 —
   기능 자랑보다 "무엇을 확인했는지"를 말한다.
7. 브랜드 표기는 항상 "DockLive". 한글 조사 결합 시 "DockLive가/를".
