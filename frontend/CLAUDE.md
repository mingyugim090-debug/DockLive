# DockLive Web — IA 개편 & UX 리디자인

공고 기반 제출문서 에이전트의 프론트엔드(Next.js) 개편 작업.
목표: **7개 섹션 → "프로젝트" 단일 명사 + 6단계 파이프라인**으로 재구조화.
루트 `../CLAUDE.md`(모노레포 규칙: 컬러 시스템, 금지사항 8가지, 테스트 방법)를 함께 따른다.

## 반드시 먼저 읽을 파일 (순서대로)
1. `docs/IA.md` — 개편 전후 구조, 라우트 맵, 리다이렉트 표 (실측 갱신 완료)
2. `docs/FLOWS.md` — 6단계 파이프라인 상태 머신과 화면 규칙
3. `docs/PAGE_SPECS.md` — 페이지별 수용 기준 (완료의 정의)
4. `docs/COPY_GUIDE.md` — UX 카피 규칙
5. `TASKS.md` — 마이그레이션 순서 (순서 바꾸지 말 것)

## 제품 원칙 (모든 UI 결정의 기준)

1. **명사는 '프로젝트' 하나.** 새 최상위 섹션·메뉴·모드를 추가하는 PR은 반려.
   "~스튜디오", "~모드 전환" 같은 개념이 생기려 하면 프로젝트의 단계로 흡수할 방법을 먼저 찾는다.
2. **프로젝트는 상태 머신.** 모든 프로젝트는 6단계 중 하나의 상태를 가지며,
   목록 카드와 URL에 상태가 드러나고, 재진입 시 그 지점에서 이어진다.
3. **근거는 항상 왼쪽에.** 3단계 이후 화면은 2패널: 좌=공고 근거/요구사항(읽기),
   우=작성 캔버스(쓰기). 사용자가 공고를 다시 찾으러 화면을 떠나게 하지 않는다.
4. **무결성은 보이는 기능이다.** export 전 무결성 검사 결과(C1~C5)를 배지로 노출.
   백엔드 채점기(DockLive 본체 Phase 9)와 계약: GET /api/projects/:id/integrity
5. **스킵 가능, 손실 없음.** 단계 건너뛰기 허용(양식만 채우기 = 4단계 직행).
   뒤로 가도 입력·초안은 보존. 파괴적 액션(프로젝트 삭제)만 확인 모달.

## 작업 규칙
- 기존 페이지를 지우기 전에 새 구조가 먼저 동작해야 한다 (TASKS.md의 스트랭글러 순서).
- 기존 URL은 전부 docs/IA.md의 리다이렉트 표대로 301 처리. 죽은 링크 금지.
- 삭제한 기능의 코드는 첫 스프린트 동안 `legacy/`로 이동만 (rm 금지) — 롤백 대비.
- 매 태스크 완료 전: 빌드 통과 + PAGE_SPECS.md 해당 페이지 체크리스트 전 항목 확인
  결과를 작업 로그에 남긴다.
- 카피 신규 작성/수정은 반드시 COPY_GUIDE.md 규칙 통과.

## 디자인 방향 (기존 톤 유지·정제)
- 현재의 그린 포인트 + 크림/화이트 톤 유지. 리브랜딩 아님 — 구조 개편이다.
- 새 컴포넌트: 단계 스테퍼(1~6), 프로젝트 상태 카드, 무결성 배지, 2패널 캔버스.
- 상태 색: 진행=그린 계열 1종, 대기=중립, 실패/미채움=적색 1종. 3색 이상 금지.
- "Windows 정품 인증" 같은 데모 환경 노출 요소는 스크린샷/시연 전 점검 목록에 포함.
